Online Combat Flow Visual Reference

This page explains how Gravity Canyon should feel online: the client may predict movement and local firing feedback, but the server owns combat truth. The target is no visible projectile correction in mid-air.

Current slice status: Phaser now has pushed movement/fire intents, a server-time heartbeat, client vehicle smoothing, and server-aged shot replay. Full server projectile paths, terrain diffs, damage, KOs, and replay events are still the next larger server-authority slice.

Architecture

The browser sends commands. The server validates and owns match state. The client can draw responsive movement and firing feel, but damage, terrain, KOs, and round results are server facts.

Client presentation Server validation Authoritative truth

Current Tiny Pilot

This pilot is a small network-feel layer on top of the existing Colyseus snapshots. It is meant to prove smoother online feel before we replace the remaining local combat truth.

Shared Clock Room snapshots include serverTimeMs, so clients can align countdowns and replay event age against the server heartbeat.
Remote Movement Other players' vehicles interpolate between recent server snapshots instead of jumping directly from one received position to the next.
Local Prediction The active player's browser can move immediately, then softly correct toward server truth unless the drift becomes large enough to snap.
Shot Replay Timing A newly received server shot replay advances to the shot's current server-time age, so a late client does not start the projectile from frame zero.

Movement Sync Before Fire

Movement is where prediction belongs. The active player sees responsive movement while the client pushes movement intents. Server position patches keep the firing state aligned before the player releases the shot.

Fire Without Mid-Air Correction

On release, the shooter should see the projectile immediately. The way to make that safe is not to bend the projectile later; it is to keep movement synchronized before release and run the same deterministic shot math on client and server.

Current Code Touchpoints

The current intent bridge lives in src/match/OnlineMatchIntentPublisher.ts and is passed into MatchScene from src/main.ts. The server receives those pushed commands through submitTurnIntent in server/rooms/GravityCanyonRoom.ts.

The current smoothing/replay pilot lives in src/match/MatchSceneOnlineVehicleSync.ts, src/match/OnlineVehicleSmoother.ts, src/match/OnlineMatchStateSync.ts, and src/match/MatchSceneOnlineSync.ts. The shared server clock is published through server/rooms/turnAuthority.ts and server/schema/GravityCanyonState.ts.
